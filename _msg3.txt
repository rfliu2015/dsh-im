docs: explain configuration inheritance when replacing the official build

A machine that already runs @xmanrui/dsh-im and has bots configured needs to
know two things before switching to this fork: whether the configuration
survives, and whether the official package must be removed first.

Both answers come from where configuration lives. It is not inside the plugin
package: each channel resolves its own root from the channel name
(`plugin-src/host/channels/shared/production.mjs:35` and siblings),

    resolve(config.dataDir ?? join(dshHome, 'integrations', `dsh-${channel}`))

so it is keyed by neither package name nor version. Because both packages are
named @xmanrui/dsh-im, installing the fork replaces the official build in
place: cordis.patch.yml needs no edit and every bot keeps working. Removing
first is unnecessary and actively worse -- it leaves the patch layer pointing
at a missing entry -- and it does not reset anything anyway, since
`dsh-im uninstall` only runs `plugin remove` (bin/dsh-im.mjs:91) and touches
nothing under integrations/.

Document the backup step (the version still moves from 5.6.x to 5.7.0), the
profile check that decides between --profile desktop and --profile web, and a
three-step verification. Add it to the package files list so an installed copy
carries it too.
